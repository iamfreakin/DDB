# AI 에이전트 활용 프로젝트 보고서

- 상태: Review
- 작성 목적: 미니프로젝트에서 AI 에이전트를 어떻게 활용했는지 설명한다.
- 대상 독자: 수업 발표자, 평가자, 이후 같은 방식으로 프로젝트를 진행할 학습자

## 1. 프로젝트 개요

본 프로젝트는 소상공인이 전문 마케팅 지식 없이도 브랜드 분석, 홍보 전략, SNS
게시물, 광고 포스터, 콘텐츠 캘린더를 만들 수 있도록 돕는 웹 서비스다.

핵심 흐름은 다음과 같다.

```text
가게 정보 입력
-> 브랜드 분석
-> 홍보 전략 추천
-> SNS 게시물 생성
-> 광고 포스터 생성
-> 콘텐츠 캘린더 작성
-> 결과물 저장·비교
```

프로젝트의 중요한 특징은 단순히 AI가 문장을 생성하는 데 그치지 않고, AI 생성물을
사용자가 검토·수정·승인하는 작업 흐름으로 구성했다는 점이다.

## 2. AI 에이전트 활용 목표

이 프로젝트에서 AI 에이전트는 코드를 대신 작성하는 도구가 아니라, 기획자·설계자·
개발 보조자·검증 보조자의 역할을 함께 수행했다.

활용 목표는 네 가지였다.

1. 아이디어를 실제 구현 가능한 제품 흐름으로 구체화한다.
2. 요구사항, 설계, 테스트 문서를 세분화해 작업 기준을 만든다.
3. 백엔드, 프론트엔드, AI 공급자 구조를 일관된 방식으로 구현한다.
4. 구현 결과를 테스트와 문서로 검증해 발표 가능한 상태로 정리한다.

## 3. 진행 방식

### 3.1 아이디어 구체화

처음에는 "AI 에이전트를 활용한 웹 미니프로젝트"라는 넓은 주제에서 시작했다.
AI 에이전트와 대화하며 여러 아이디어를 비교했고, 최종적으로 소상공인을 위한
브랜드 콘텐츠 제작 도구를 선택했다.

아이디어를 정할 때는 다음 기준을 사용했다.

- 사용자가 쉽게 이해할 수 있는 문제인가
- AI 생성 기능이 자연스럽게 들어가는가
- 웹 화면으로 시연하기 좋은가
- 문서와 기능을 여러 단계로 나누기 좋은가
- API 키가 없어도 Mock으로 흐름을 확인할 수 있는가

이 기준을 통해 단순 챗봇보다 제품 흐름이 뚜렷한 서비스로 방향을 정했다.

### 3.2 문서 우선 개발

AI 에이전트에게 바로 코드를 작성하게 하지 않고, 먼저 문서 구조를 만들었다.
문서는 제품 범위, 요구사항, UX, 아키텍처, AI 정책, 데이터/API, 테스트, 개발 계획으로
나누었다.

문서 우선 방식의 장점은 다음과 같았다.

- 기능 추가 시 기준 문서를 먼저 확인할 수 있었다.
- 요구사항 ID와 테스트 ID를 연결해 누락을 줄일 수 있었다.
- AI 에이전트가 이전 결정과 충돌하지 않게 작업할 수 있었다.
- 발표 시 "왜 이렇게 만들었는지" 설명하기 쉬웠다.

특히 `FR-101`부터 `FR-117`까지 기능 요구사항을 부여하고, 테스트 시나리오와
연결한 점이 프로젝트 관리에 도움이 되었다.

### 3.3 AI 에이전트에게 준 작업 지시 방식

AI 에이전트에게는 한 번에 "전부 만들어줘"라고만 지시하지 않고, 단계별로 목표를
나누어 요청했다.

예시는 다음과 같다.

```text
문서 구조부터 만들어줘.
백엔드 API부터 구현해줘.
프론트를 Next.js로 교체해줘.
이미지 생성은 API 키가 있을 때만 호출하고, 없으면 Mock으로 처리해줘.
캘린더도 최신 상태를 반영하게 해줘.
```

이처럼 단계별로 요청하면 AI 에이전트가 현재 코드와 문서를 읽고, 필요한 범위만
수정하고, 테스트까지 이어가기 쉬웠다.

## 4. AI 에이전트의 주요 역할

### 4.1 제품 기획 보조

AI 에이전트는 아이디어를 단순히 추천하는 데 그치지 않고, 사용자의 요구를 제품
흐름으로 정리했다.

최종 제품 흐름은 다음과 같이 구성되었다.

- 가게 정보 입력
- 브랜드 분석 생성
- 브랜드 분석 수정 및 승인
- 캠페인 전략 생성
- SNS 게시물 생성
- 게시물 문구 변형 선택
- 포스터 브리프 생성
- 광고 포스터 생성
- 콘텐츠 캘린더 작성
- 결과 저장, 비교, 내보내기

이 흐름은 발표자가 서비스 목적을 설명하기에도 좋고, 실제 사용자가 따라가기에도
자연스럽다.

### 4.2 설계 문서 작성 보조

AI 에이전트는 기능 요구사항, API 명세, 데이터 모델, 테스트 시나리오를 서로 연결된
문서로 작성했다.

문서화 과정에서 중요하게 둔 원칙은 다음과 같다.

- 확정된 내용과 후속 확장을 구분한다.
- AI 생성 결과는 초안이며 사용자가 검토해야 한다.
- API 키와 개인정보는 코드나 DB에 저장하지 않는다.
- 외부 API 실패를 예외가 아니라 정상적인 실패 시나리오로 다룬다.
- Mock 공급자를 두어 API 키 없이도 전체 흐름을 검증한다.

### 4.3 구현 보조

AI 에이전트는 기존 문서를 읽고 기능을 구현했다. 구현 과정에서 중요한 점은
비즈니스 로직, AI 생성 로직, UI 로직을 분리한 것이다.

예를 들어 텍스트 생성과 이미지 생성은 각각 교체 가능한 공급자 인터페이스로
분리했다. 이 덕분에 API 키가 없는 경우에는 Mock 생성기를 사용하고, 사용자가 키를
입력하면 OpenAI API를 사용하는 방식으로 전환할 수 있었다.

이미지 생성도 단순히 "이미지를 만든다"가 아니라 다음 원칙으로 설계했다.

- AI는 글자가 없는 배경 이미지를 생성한다.
- 앱은 정확한 한글 제목과 보조 문구를 이미지 위에 합성한다.
- 사용자는 생성 결과를 미리 보고 승인한다.
- 승인 전 결과는 초안으로 취급한다.

### 4.4 검증 보조

AI 에이전트는 구현 후 다음 검증을 수행했다.

- 백엔드 API 테스트
- 프론트엔드 lint
- Next.js production build
- 브라우저에서 실제 화면 확인
- 생성된 포스터 PNG 확인
- 문서와 요구사항 추적표 갱신

이 과정은 AI 에이전트를 단순 코드 작성자가 아니라, 작업을 끝까지 확인하는 개발
파트너로 활용한 사례다.

## 5. AI 에이전트 활용 시 효과적이었던 방법

### 5.1 "역할"보다 "산출물"을 명확히 요청하기

AI에게 "기획자처럼 해줘"라고만 말하는 것보다 "기능 요구사항 문서를 만들어줘",
"API 명세를 갱신해줘", "테스트까지 통과시켜줘"처럼 산출물을 지정하는 방식이 더
효과적이었다.

### 5.2 작업 단위를 작게 나누기

처음부터 완성 서비스를 요구하기보다 문서, 백엔드, 프론트엔드, 이미지 생성,
캘린더 최신화처럼 작업을 나누면 결과를 확인하고 방향을 수정하기 쉬웠다.

### 5.3 코드보다 문서를 먼저 확인하게 하기

AI 에이전트에게 작업 전 `docs/README.md`와 관련 설계 문서를 확인하도록 규칙을
두었다. 덕분에 기능이 추가될 때 기존 요구사항과 충돌하는 일이 줄었다.

### 5.4 Mock과 실제 API를 함께 설계하기

유료 API 키가 없어도 프로젝트를 시연할 수 있어야 했다. 따라서 Mock 생성기를 먼저
두고, 사용자가 키를 입력하면 실제 API를 호출하는 방식으로 만들었다.

이 방식은 수업 프로젝트에 특히 적합하다.

- 비용 없이 기능 흐름을 보여줄 수 있다.
- API 키를 코드에 넣지 않아도 된다.
- 나중에 실제 API를 연결해도 구조를 크게 바꾸지 않는다.

### 5.5 생성 결과를 무조건 신뢰하지 않기

AI가 만든 브랜드 분석, 게시글, 포스터는 모두 초안으로 취급했다. 사용자가 수정하고
승인하는 단계를 넣어야 실제 서비스 흐름이 안정적이다.

## 6. 어려웠던 점과 해결 방법

### 6.1 아이디어 범위 조절

처음에는 너무 신박한 아이디어를 찾으려다 구현 범위가 커질 수 있었다. 이를 해결하기
위해 "웹으로 시연 가능하고, 문서화하기 좋고, 생성 AI가 자연스럽게 들어가는 기능"으로
범위를 좁혔다.

### 6.2 이미지 안의 한글 문제

이미지 생성 모델은 이미지 속 한글 문자를 정확히 쓰지 못할 수 있다. 따라서 AI가
글자를 포함한 완성 포스터를 만들게 하지 않고, 배경 이미지만 생성하게 했다. 정확한
한글 제목과 보조 문구는 애플리케이션에서 합성했다.

### 6.3 API 키 보안

API 키를 프로젝트 코드에 넣으면 보안 문제가 생긴다. 이 프로젝트는 사용자가 웹
화면에서 직접 키를 입력하고, 브라우저 세션에만 보관하게 했다. 백엔드는 요청 처리
중에만 키를 사용하고 저장하지 않는다.

### 6.4 생성 시간이 긴 문제

AI 생성 요청은 일반 API보다 오래 걸릴 수 있다. 그래서 프론트엔드 프록시와 백엔드
공급자 호출에 시간 초과 처리를 두고, 실패해도 입력 내용을 유지하고 재시도할 수
있게 했다.

## 7. 결과물

최종 프로젝트는 다음 기능을 포함한다.

- 브랜드 프로필 생성
- 브랜드 분석 생성, 수정, 승인
- 4주 캠페인 전략 생성
- Instagram 게시물 8개 생성
- 게시물별 문구 변형 생성과 선택
- 포스터 브리프 생성과 수정
- 광고 포스터 이미지 생성, 미리보기, 다운로드, 승인
- 콘텐츠 캘린더 생성과 최신화
- 브랜드 보고서 Markdown 내보내기
- 캘린더 CSV 내보내기
- Mock/OpenAI 공급자 전환

## 8. 결론

이 프로젝트에서 AI 에이전트는 아이디어 생성, 문서화, 구현, 테스트, 개선까지 전
과정에 활용되었다. 중요한 점은 AI에게 모든 결정을 맡기는 것이 아니라, 사용자가
방향을 정하고 AI가 그 방향을 빠르게 구체화하도록 협업한 것이다.

AI 에이전트를 효과적으로 활용하려면 다음 세 가지가 중요하다.

1. 목표와 산출물을 명확히 말한다.
2. 문서와 테스트로 결과를 검증한다.
3. 생성 결과는 사용자가 검토하고 승인하는 흐름으로 설계한다.

이 방식은 짧은 시간 안에 수업용 미니프로젝트를 제품처럼 완성도 있게 만드는 데
효과적이었다.
