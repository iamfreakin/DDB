# 문서 작성 규칙

- 상태: Draft
- 목적: 프로젝트 문서의 형식과 관리 원칙을 통일한다.

## 공통 머리말

각 문서는 가능하면 상태, 목적, 관련 문서, 최종 변경일을 기록한다.

## 식별자 규칙

| 대상 | 형식 | 예시 |
|---|---|---|
| 기능 요구사항 | `FR-###` | `FR-101` |
| 비기능 요구사항 | `NFR-###` | `NFR-201` |
| 사용자 스토리 | `US-###` | `US-101` |
| 테스트 케이스 | `TC-###` | `TC-101` |
| 의사결정 기록 | `ADR-###` | `ADR-001` |

## 변경 원칙

- 결정 이유를 지우지 말고 의사결정 기록에 남긴다.
- 중복된 정의는 만들지 않고 원본 문서를 링크한다.
- 수치 기준은 `빠르게`, `충분히` 대신 측정 가능한 값으로 작성한다.
